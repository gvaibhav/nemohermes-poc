# NemoHermes: Sandboxed Hermes Agent on macOS via NVIDIA NemoClaw

Run a **Hermes Agent** (`nemohermes`) inside an **NVIDIA OpenShell** sandbox on macOS (Docker Desktop) powered by **Google Gemini API**.

> **Primary PoC:** Toil Reduction via `SKILL.md` — a Self-Evolving Runbook that persists SRE tribal knowledge across sessions.

### 1. Prerequisites
- **macOS** with **Docker Desktop** installed and running
- **Python 3.10+**
- **Google Gemini API Key** — get one at [aistudio.google.com](https://aistudio.google.com/)

```bash

# Edit config/credentials.env → set your GEMINI_API_KEY
```

### Troubleshooting
- **Docker Desktop not running:** Ensure Docker Desktop is launched and running. The setup script will error if not found.
- **GEMINI_API_KEY not set or invalid:** Ensure you copied `config/credentials.env.example` to `config/credentials.env` and added your API key. If the key is invalid, the PoC in `--live` mode will fail with a 400 error.
- **Orphan processes after a crash:** The PoC scripts handle graceful shutdown natively, but if interrupted aggressively, kill stray bash processes manually: `pkill -f "while true; do echo leak"`.
- **ModuleNotFoundError:** Ensure `__init__.py` is present in both `usecases/` and `tests/` to be treated as packages. Add missing modules to `requirements.txt` and re-run setup.

## Security Notes
- **Never** commit `config/credentials.env` — it is in `.gitignore`
- The PoC runner spawns bash loops on the host for demonstration. In production, these run inside the OpenShell container with Landlock/seccomp isolation.
