## 3. Environment Setup

### 3.1 Prerequisites
- **macOS** (Apple Silicon or Intel)
- **Docker Desktop** — installed and **running** (`docker info` must succeed)
- **Python 3.10+** with `pip`
- **Git**

### 3.2 One-Command Setup
```bash
bash scripts/setup_nemoclaw.sh
```

This script is idempotent and will:
1. Verify Python 3.10+ and Docker Desktop are running
2. Copy `config/credentials.env.example` → `config/credentials.env` (if missing)
3. Install Python dependencies from `requirements.txt`
4. Clone `https://github.com/NVIDIA/nemoclaw.git` into `nemoclaw_src/`
5. Attempt NemoClaw CLI initialization with Hermes agent

### 3.3 Credentials
Set `GEMINI_API_KEY` in `config/credentials.env`:
```env
GEMINI_API_KEY=<your-actual-key-from-aistudio.google.com>
```

**CRITICAL**: Never commit `credentials.env`. It is in `.gitignore`.

## 5. Coding Conventions & Rules

### 5.1 Python Standards
- Type annotations on all function signatures (params + return)
- Docstrings on all public functions and classes
- Use `pathlib.Path` (not `os.path`) for filesystem operations
- Resolve paths relative to `PROJECT_ROOT = Path(__file__).resolve().parent.parent`, not `os.getcwd()`
- Use `yaml.safe_load()` — never `yaml.load()` without `Loader`

### 5.2 SKILL.md File Format
All skill files must follow this structure:
```markdown
---
name: <skill_name>
version: "1.0"
description: <human-readable description>
triggers:
  - "<exact trigger phrase>"
  - "<alternate trigger phrase>"
author: hermes-agent
---

# <Skill Title>

## Description
<What this runbook does>

## Action Sequence
1. <Step with fenced bash code block>
2. <Step with fenced bash code block>

## Rollback
<How to undo if something goes wrong>
```

### 5.3 Process Safety
- Track all spawned subprocess PIDs in a list
- Always clean up spawned processes in a `finally` block
- Use `signal.SIGKILL` (not raw `9`) via `os.kill(pid, signal.SIGKILL)`
- Verify process death with `ps -p <PID>` after killing

### 5.4 Security Rules
- **Never** commit API keys, tokens, or `.env` files
- **Never** use `eval()` or pipe untrusted URLs to `bash`
- Validate all YAML input with `yaml.safe_load()`
- Grep for secrets before every commit: `git diff --cached | grep -i "api_key\|secret\|token\|password"`

## 6. Maker-Checker Delegation Workflow

This repo uses a **Maker-Checker** pattern for Jules delegation:

1. **Maker** (build agent): Reads `prompts/jules_maker_prompt.md` → implements code changes → opens a PR
2. **Checker** (audit agent): Reads `prompts/jules_checker_prompt.md` → reviews the Maker's PR → runs tests → generates `CHECKER_REPORT.md`

### Pull Request Rules
- All tests must pass: `python3 -m unittest discover -s tests -v`
- No secrets in any committed file (check with `git grep -i api_key`)
- `__init__.py` must exist in `usecases/` and `tests/`
- Every new Python function must have type annotations and a docstring
